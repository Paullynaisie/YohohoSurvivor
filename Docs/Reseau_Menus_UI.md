- **Bugs réseau bloquants (2026-11-12) : freeze au choix d upgrade, joueur « mort » au lancement** :
  - **Cause trouvée du freeze** : pendant la pause du choix d upgrade le temps du serveur est figé, rien n est répliqué sans `ForceNetUpdate`. `AYSPlayerCharacter::ChangeClass` (upgrade de classe appliquée à la fin d une sélection, souvent suivie d une autre : plusieurs niveaux d un coup, récompense de doublons de classe puis level up) détruisait / recréait / possédait le personnage SANS réplication forcée : le client ne recevait ni le nouveau personnage ni la possession (et la relance automatique de la possession du moteur, dans PlayerTick, ne tourne pas en pause) ; son menu exige un personnage -> caché, le serveur l attend pour toujours. Corrigé : `ForceNetUpdate` du contrôleur, du nouveau personnage et du PlayerState dans `ChangeClass` et la réanimation du Medic ; à chaque début de sélection (`StartUpgradeSelection`) contrôleur et personnage de chaque joueur forcés ; le menu prend le personnage du PlayerState si la possession n est pas encore arrivée (`AYSPlayerController::GetUpgradeMenuCharacter`).
  - **Filet de sécurité (proposition de Paul)** : `AYSGameMode::UpgradeResyncInterval` 5 s (catégorie `Level|Network`, 0 = jamais) : sur le serveur, chaque contrôleur d un client qui n a pas encore choisi (`AYSPlayerController::TickUpgradeResync`, temps réel) -> `AYSGameMode::ResyncPlayer` (contrôleur, personnage, PlayerState, GameState, pause en réplication forcée ; `ClientRestart` si le client n a pas confirmé son personnage, `AcknowledgedPawn`) puis `ClientCheckUpgradeSelection(nombre de propositions)` : le client qui affiche déjà ses propositions ne fait rien, sinon `ServerRequestUpgradeResync` -> `PlayerRequestedUpgradeResync` = nouvelles propositions du même type pour lui (relances gardées) + resync. Logs `[YSResync]` (Warning « upgrades pas affichées » = le filet a servi).
  - **Joueur « mort » au lancement** : l hôte affiche un allié mort quand son PlayerState n a pas de personnage. `AYSGameMode::SpawnDefaultPawnAtTransform` faisait apparaître le personnage sans règle de collision et sans log : dans la chaloupe (places serrées, autre joueur ou HiredMouss à côté) l apparition pouvait échouer en silence. Corrigé : `AdjustIfPossibleButAlwaysSpawn` + log Error si elle échoue quand même. Filet (proposition de Paul) : `AYSGameMode::RespawnMissingPlayers` = joueur prêt, pas mort, sans personnage alors que la partie a commencé -> `RestartPlayer` + resync ; appelé au débarquement de la chaloupe (`AYSFlowMode::OnGameBoatLanded`, qui resynchronise aussi tous les autres joueurs) et toutes les `MissingPawnCheckInterval` 5 s hors pause (Warning « prêt, pas mort, mais sans personnage »).
  - Debug : `-YSGodAll` (serveur) = aucun personnage de joueur ne prend de dégâts (tests en 2 fenêtres : le `god` de la console ne touche que l hôte).
  - Vérifié en 2 fenêtres (FlowMap) : récompense de doublons de classe du client (Cannoneer -> Artilleur) puis 3 level up enchaînés pendant la pause : nouveau personnage reçu par le client en 0.1 s, sélections terminées, partie reprise ; client qui ne choisit pas : vérifié toutes les 5 s, menu bien affiché donc rien d autre. Pas reproduit en local : le freeze d origine et le joueur mort au lancement (les deux corrections visent les causes trouvées dans le code ; les filets couvrent le reste). Non testé : le cas où le filet régénère les propositions (aucun menu manquant en test).
