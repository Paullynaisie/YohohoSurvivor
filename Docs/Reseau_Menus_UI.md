# Réseau, Steam, menus, widgets

Pause et réplication, Steam, menu principal, widgets C++ (icônes, barres de vie, chiffres de dégâts).

Notes de travail détaillées, déplacées de CLAUDE.md le 2026-11-10 (contenu inchangé, ordre d origine). Les entrées datées les plus récentes remplacent les valeurs plus anciennes ; « ailleurs » / « au-dessus » peut renvoyer à un autre fichier de Docs/.

- `Source/YohohoSurvivor/UI/YSAbilityIconWidget` : icône carrée construite en C++ (pas de Widget Blueprint), voile + secondes de recharge ; créée et rafraîchie par `AYSPlayerController` (bas-centre de l'écran).
- `Source/YohohoSurvivor/UI/YSHealthBarWidget` : barre de vie (WidgetComponent screen-space `HealthBar` des NME, cachée si PV max, « X / Y »). `MaxHealth` et `Health` répliquées (`OnRep_Health`). Le joueur local n a pas de barre au-dessus de lui (HUD) ; les alliés ont leur `Nameplate` (pseudo + PV).
- `Source/YohohoSurvivor/Core/YSGameState` : `ReportDamage` (serveur) -> `MulticastDamageNumber` (montant, impact, PlayerState attaquant/victime) ; chaque machine choisit la couleur selon son joueur local et spawn un `AYSDamageNumber` local (non répliqué, 1 s, monte et s'efface). Couleurs réglables sur `AYSDamageNumber`. GameState de `BP_TestGameMode`.
- **Pause et réplication** : pendant la pause (choix d upgrade), le temps du monde est figé et les acteurs (PlayerState surtout, ~1 envoi/s) ne sont plus répliqués d eux-mêmes : tout changement d état pendant la pause doit appeler `ForceNetUpdate()` (fait dans les setters d upgrade du PlayerState / GameState, dans `ApplyUpgrade`, et sur le `WorldSettings` après `SetPause` / `ClearPause` : sinon la pause n arrive jamais aux clients et leurs NME continuent d avancer), sinon les clients restent bloqués. Log `[YSPause]` à chaque changement de pause (toutes les machines). Log `[YSUpgradeMenu]` à l affichage / masquage du menu (clients compris). `-YSAutoUpgrade` : choisit automatiquement la première proposition (tests réseau).
- **Steam (AppID 480 = Spacewar, gratuit, en attendant un AppID du jeu)** : plugins `OnlineSubsystemSteam` + `SteamSockets` (.uproject), modules `OnlineSubsystem` / `OnlineSubsystemUtils` ; DefaultEngine.ini `[OnlineSubsystem] DefaultPlatformService=Steam`, `[OnlineSubsystemSteam]` (`SteamDevAppId=480`, `bRelaunchInSteam=false`, `bInitServerOnClient`, `bAllowP2PPacketRelay`, `bUseSteamNetworking=false` = sockets Windows par défaut). Steam doit être lancé et connecté AVANT le jeu, sinon le moteur se rabat sur le sous-système NULL (mode IP seulement ; éditeur / PIE : toujours NULL). Partie Steam = lobby (session `NAME_GameSession`, 4 joueurs `MaxOnlinePlayers`, clé `YOHOHOSURVIVOR=1` car l AppID 480 est partagé par tous les développeurs : la recherche ne garde que nos lobbies, filtre de distance régional de Steam) ; `UYSGameInstance` : `HostOnlineGame` (CreateSession puis HostMap en `?listen`), `FindOnlineGames` / `JoinOnlineGame`, invitation acceptée (`OnSessionUserInviteAccepted`, en jeu ou au lancement par `+connect_lobby`) -> `JoinSessionResult` (quitte d abord le lobby en cours) -> `GetResolvedConnectString` (« steam.<SteamID>:7777 ») -> `ClientTravel` ; `DestroyOnlineSession` au retour au menu (`ReturnToMenu`, et à l affichage du menu principal). Driver réseau : `GameNetDriver` reste IpNetDriver dans la config ; `UseSteamNetDriver` le passe à `SteamSocketsNetDriver` (relais Steam, pas de port à ouvrir) pour une partie Steam et le remet à IpNetDriver pour une partie par IP. `AYSGameMode::PreLogin` accepte les identifiants d un autre sous-système (hôte Steam + client sans Steam en IP, sinon `incompatible_unique_net_id`). Pseudo par défaut = pseudo Steam (tronqué à `MaxNicknameLength`), « Player N » sans Steam. Écran de sélection : bouton « Inviter des amis (Steam) » (`Layout|Invite`, visible seulement dans une partie Steam) = overlay Steam (`ShowInviteFriendsUI`). Logs `[YSSteam]`. Debug : `YSInviteFriends` (PlayerController), `YSSteamHost`, `YSSteamFind [index à rejoindre]` (GameInstance, marchent dans le menu : `-ExecCmds="YSSteamHost"`). Vérifié sans fenêtre (`-nullrhi`) : lobby créé, SteamSockets en écoute sur les relais, recherche ok, mode IP (hôte Steam + client NULL) ok. **Limite de test : un seul Steam par PC** (une 2e instance ne l initialise pas : « Failed to initialize Steam » -> NULL) : le test hôte / client Steam se fait sur 2 PC avec 2 comptes Steam. Passer à un vrai AppID = changer `SteamDevAppId`.
- Menu principal : `/Game/Maps/MainMenu` (GameDefaultMap du jeu ; GameMode Override = `Core/YSMenuGameMode`, créée par `Tools/EditorScripts/setup_main_menu.py`) -> `Player/YSMenuPlayerController` -> `UI/YSMainMenuWidget` (C++, deux colonnes, `Layout` : `ColumnWidth`, `ColumnSpacing`, `ButtonHeight`, `GameButtonHeight` ; gauche **Steam** : état (« Connecté : pseudo » ou Steam non détecté = boutons grisés), Héberger (Steam), Chercher les parties (un bouton par lobby trouvé : hôte, joueurs / max ; pleine = grisé) ; droite **IP** : Héberger en IP, IP locales du PC + bouton « Copier mon IP » (première IP dans le presse-papier, `FPlatformApplicationMisc::ClipboardCopy`, module ApplicationCore), champ IP + Rejoindre par IP (Entrée) ; Quitter et l erreur réseau qui a ramené au menu en dessous). `Core/YSGameInstance` (`GameInstanceClass`) : `HostGame` = `HostMap` en `?listen` (port 7777), `JoinGame` = `ClientTravel` vers l IP (dernière IP mémorisée dans GameUserSettings.ini), `ReturnToMenu` = `MenuMap` ; `HostMap`/`MenuMap` dans DefaultGame.ini `[/Script/YohohoSurvivor.YSGameInstance]`. Erreurs réseau via `GEngine->OnNetworkFailure/OnTravelFailure` (le moteur renvoie seul sur la GameDefaultMap). Échap en partie = `YSLeaveGame` (retour menu ; hôte : renvoie aussi les clients au menu). `InitialConnectTimeout` 15 s. L éditeur démarre toujours sur GameMap (PIE inchangé).
