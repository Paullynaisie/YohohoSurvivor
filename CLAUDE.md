# YohohoSurvivor

Jeu **top-down multijoueur en ligne (1 à 4 joueurs par partie)**, Unreal Engine **5.8**, C++.
Langue de travail avec l'utilisateur (Paul) : **français**.

## Build

- Paul travaille sur plusieurs PC : **aucun chemin absolu en dur**. Le projet = racine du dépôt (dossier de travail courant, `$PWD`). Le moteur se retrouve via le registre (installation Epic Games Launcher) ; si la clé est absente, demander à Paul où est UE 5.8 sur ce PC.
  ```
  $UE = (Get-ItemProperty "HKLM:\SOFTWARE\EpicGames\Unreal Engine\5.8" -ErrorAction SilentlyContinue).InstalledDirectory
  if (-not $UE) { $UE = "C:\Program Files\Epic Games\UE_5.8" }  # clé pas toujours créée par le launcher
  ```
- Toolchain : UE 5.8 exige **MSVC 14.50+** (Visual Studio 2026, composants dans `.vsconfig` ; 14.51 fonctionne). Avec MSVC 14.38/14.44 (VS 2022) le build échoue dans les en-têtes du moteur (erreur C7539 dans `ContainerAllocationPolicies.h`). Les `Target.cs` fixent `WindowsPlatform.CompilerVersion = "Latest"` : prioritaire sur le `%APPDATA%\Unreal Engine\UnrealBuildTool\BuildConfiguration.xml` global, qui peut forcer un vieux compilateur pour les autres projets UE de Paul (ne pas modifier ce fichier global). En PowerShell, **mettre entre guillemets** les arguments contenant des points (`"-CompilerVersion=…"`, `"-Project=…"`), sinon ils sont coupés.
  Exécutables : `$UE\Engine\Binaries\Win64\UnrealEditor.exe` / `UnrealEditor-Cmd.exe`.
- Compiler (éditeur fermé, ou sinon utiliser Live Coding Ctrl+Alt+F11 dans l'éditeur) :
  ```
  & "$UE\Engine\Build\BatchFiles\Build.bat" YohohoSurvivorEditor Win64 Development -Project="$PWD\YohohoSurvivor.uproject" -WaitMutex
  ```
- Régénérer la solution VS (après ajout/suppression de fichiers) :
  ```
  & "$UE\Engine\Build\BatchFiles\Build.bat" -projectfiles -project="$PWD\YohohoSurvivor.uproject" -game -rocket -progress
  ```
- Si `UnrealEditor` est ouvert avec Live Coding actif, le build en ligne de commande échoue : demander à Paul de fermer l'éditeur ou de lancer Live Coding.
- Les warnings C4996 venant de `Engine/` (Niagara, Character.h) sont connus et ne concernent pas notre code.
- Le packaging compile en **unity build** (plusieurs `.cpp` fusionnés) alors que les builds éditeur incrémentales non : les helpers `namespace { }` doivent avoir des noms uniques au projet (sinon C2084 seulement au packaging) ; mettre ceux d un fichier dans un namespace nommé (ex. `YSMainMenu::`).
- Après chaque modification C++, **compiler pour vérifier** avant de déclarer la tâche terminée.

## Structure

- `Source/YohohoSurvivor/` : module principal (classes de base du template Top Down : Character, GameMode, PlayerController).
- `Source/YohohoSurvivor/Variant_TwinStick/` : base la plus proche d'un « survivor » (projectiles, ennemis IA via StateTree, spawner, pickups, AoE). **Point de départ du gameplay.**
- `Source/YohohoSurvivor/Variant_Strategy/` : variante RTS du template, probablement à supprimer.
- Les dossiers de variantes sont dans `PublicIncludePaths` du `.Build.cs` : à mettre à jour si on déplace/supprime des dossiers.
- `Source/YohohoSurvivor/Player/YSPlayerCharacter` : personnage joueur (ZQSD/WASD/flèches, input créé à l'exécution, `MoveSpeed` réglable). Regarde le curseur (`bUseControllerRotationYaw`), strafe via `StrafeBlendSpace` joué en mode SingleNode (pas d'Anim Blueprint). Parent du BP `/Game/Placeable/Character/PlayerCharacter_mouss`.
- `Source/YohohoSurvivor/Player/YSPlayerController` : curseur viseur, calcule `AimLocation` (souris projetée sur le plan du pawn) et met la rotation de contrôle vers ce point ; le CMC l'envoie au serveur avec les mouvements.
- `/Game/Placeable/Character/Anims/BS_Player_Strafe` : BlendSpace 2D (X = direction -180..180 relative au regard, Y = vitesse 0..600 ; idle / marche 200 / course 600 dans 8 directions).
- Joueur (DA primitives) : `BodyPivot` (scene, origine capsule) porte `BodyMesh` (cylindre ; mesh squelettique vide, donc pas de strafe animé), `FaceDecal`, et les mains `LeftHand` / `RightHand` (scene, non scalées = points d attache des armes, `GetLeftHand()`/`GetRightHand()` ; position monde absolue calculée par `UpdateHands` : cible `HandLocation` (main droite, gauche = Y inversé) ou `HandLocation` de l arme si `bOverrideHandLocation`, rotation `HandRotation` (gauche = Yaw/Roll inversés) ou celle de l arme si `bOverrideHandRotation`, + oscillation Perlin `HandSwayAmplitude`/`HandSwaySpeed`, suivie avec retard `HandFollowSpeed`) avec leurs sphères `LeftHandMesh` / `RightHandMesh` (matériau copié de BodyMesh dans OnConstruction si `bHandsUseBodyMaterial`). Armes : `LeftHandWeapon` / `RightHandWeapon` = `UChildActorComponent` sur les mains (owner = perso, acteur enfant répliqué spawné par le serveur), classes données par le **set d arme** du perso (`WeaponSet`, catégorie 3C|Weapons : Data Asset `Weapons/YSWeaponSet` {`DisplayName`, `RightHandWeapon`, `LeftHandWeapon`} dans `/Game/Core/WeaponSets` : `DA_WeaponSet_SabrePistolet` (Mouss), `DA_WeaponSet_AkimboBattlePetoir`, `DA_WeaponSet_AkimboSabre` (obtenus par l upgrade de classe) ; `Tools/EditorScripts/setup_weapon_sets.py`), sinon par `LeftHandWeaponClass` / `RightHandWeaponClass` (tests, éditables seulement sans set) ; appliquées dans OnConstruction -> visuel dans l éditeur ; `GetHeldWeapons()`. Clic gauche = actions des deux mains ; main principale = droite ; akimbo (`IsAkimbo()` : même classe d arme dans les deux mains) : droite puis gauche après `AkimboFireDelay` de l ACTION de la main principale (catégorie `Akimbo` de chaque action : Coup d Petoir, Auto shot, Coup d sabre, réglables séparément) avec une **recharge unique** : la main droite se bloque `GetActivationLockDuration()` = recharge + délai akimbo, les deux mains redeviennent prêtes ensemble une fois les deux actions finies (Coup d Petoir et Coup d sabre ; icône comprise). Les upgrades ne dépendent plus des mains : Ability et Auto atk s appliquent à tout le set (voir upgrades). Debug : `YSFire` (comme un clic gauche), log Verbose `[YSAbility]` (heure d activation / prête). L icône UI suit la main droite, sinon la gauche. Les mains pivotent (yaw, `HandAimSpeed`) vers la cible de visée assistée du Coup d Petoir de leur arme (calculée depuis le regard du perso, donc identique sur toutes les machines ; en jeu seulement).
- `Source/YohohoSurvivor/Weapons/YSWeapon` : arme (Root, `Mesh`, `Muzzle`, `DisplayName`), `GetAction()` = premier `UYSAbilityComponent` de l acteur (ajouté dans le BP de l arme), `GetHolder()` = owner pawn. Recul : réglages sur chaque action de tir (`UYSCoupDPetoirAbility`, donc aussi l Auto shot, catégorie `Recoil` : `GetRecoilAlpha()` d après sa dernière activation, coup EaseOut `RecoilKickDuration`, retour EaseInOut `RecoilRecoverDuration`, `RecoilPitch`, `RecoilKickBack`) ; `AYSWeapon::GetRecoil` prend l action de tir la plus récente ; le perso cabre la main et la recule le long de l axe de l arme, après le lissage. **Priorités des actions** (`ActionPriority` dans `YSAbilityComponent.cpp`, liste donnée par Paul : 1 Ability, 2 Auto atk) : par arme (les deux armes en akimbo), une action ne démarre pas (`CanStartByPriority`) tant qu une plus prioritaire est en cours (`IsActionInProgress` = `GetActionDuration()` depuis l activation, + `AkimboFireDelay` pour la main principale en akimbo ; Coup d Petoir / Auto shot : durée du recul ; Coup d sabre : son animation) ; en démarrant, elle interrompt les moins prioritaires (`CancelAction` serveur : anim arrêtée partout via `MulticastCancelled`, recharge rendue, main suivante de l akimbo annulée ; log Verbose « interrompue »). Réglages Akimbo / Recoil reportés depuis les armes par `Tools/EditorScripts/migrate_akimbo_recoil.py`. BP dans `/Game/Placeable/Weapons` : `BP_Arme` (base), `BP_Pistolet` (action `CoupDPetoir` : PetoirAMMO, 5 dégâts, recharge 1 s), `BP_Epee` (Coup d sabre en Auto atk), `BP_BattlePetoir` (enfant de BP_Pistolet : Coup d Petoir en Ability + composant `AutoShot` = `Abilities/YSAutoShotAbility` en Auto atk : sous-classe de Coup d Petoir, automatique, serveur : tire dès qu il est prêt et qu un NME est dans le cône de visée assistée, même projectile, 20 dégâts, recharge 1 s, akimbo comme le sabre ; `Tools/EditorScripts/setup_battle_petoir.py` ; porté par aucun perso pour l instant). `UpdateBodyPivot` (visuel, toutes machines) : inclinaison autour des pieds vers la vélocité monde (`LeanMaxAngle` 30, `LeanDuration` 0.14 s, `LeanEasing` EaseIn, `LeanEaseExponent` 2) + sautillement vertical (`HopHeight` 10 cm, `HopDuration` 0.2 s à `MoveSpeed`, cadence proportionnelle à vitesse réelle / `MoveSpeed`, `HopEasing` EaseInOut). Paramètres du perso dans la catégorie `3C` (affichée en premier via `PrioritizeCategories`). Composant BP `Head Feature` (sphère, enfant de BodyPivot) porte `Bandana` = `UYSDanglingChainComponent` (`Player/YSDanglingChainComponent` : chaîne de cylindres en Verlet, gravité + poussée vers l arrière, segments transient en coordonnées absolues ; pose de repos dans l éditeur via tick éditeur, simulation en jeu). `FaceDecal` = `UYSFaceDecalComponent` (`Player/YSFaceDecalComponent`) : propriété `FaceTexture` sur le composant -> MID transient sur `M_FaceDecal` (`/Game/Art/Materials/Decals`), le DecalMaterial de base est restauré avant sauvegarde.
- `Source/YohohoSurvivor/Abilities/YSAbilityComponent` : base des capacités (recharge `Cooldown`, `TryActivate` côté client -> RPC `ServerActivate` -> `ExecuteAbility` sur le serveur ; `ReadyServerTime` répliqué, prédit côté client). Effets visuels : `GetTimeSinceActivation()` (temps local) mis à jour par prédiction chez le tireur et par `MulticastActivated` (Unreliable) chez les autres. Paramètres BlueprintReadWrite pour les futurs upgrades.
- **Type d action** `EYSWeaponType` Melee / Gun (`UYSAbilityComponent::WeaponType`, sur l ACTION ; Gun pour les tirs, Melee pour le Coup d sabre) : servira aux comportements face aux upgrades. **Shoot system** des actions de Gun (`EYSShootSystem` : PewPew ; Shotgun / Piercing cachés, à venir), catégorie `Shoot System` : `BulletsPerBurst` / `BurstDuration` = une activation tire ses balles une par une réparties uniformément (première tout de suite, dernière à la fin ; `FireNextBullet` sur timer serveur, `FireBullet` + `MulticastBulletFired` = recul de chaque balle), puis rechargement = `Cooldown` (`GetCooldownDuration` = BurstDuration + Cooldown × CD reduction) ; rafale interrompue par `OnActionCancelled` (priorité, objet porté) ; `IsActionInProgress` vrai pendant la rafale. **Reload anim** (catégorie `Reload Anim`, après Recoil) : en fin de rafale chaque arme qui a tiré tourne sur elle-même (`MulticastReloadStarted`, `bPlayReloadAnim`, `ReloadSpinDuration` 0.35, `ReloadSpinTurns` 1, `ReloadSpinAxis` Pitch / Yaw / Roll, `ReloadSpinEaseExponent` 2 ; `AYSWeapon::GetReloadSpin` ajouté à la rotation de la main après le recul). Logs Verbose `[YSGun]` (chaque balle, rechargement). Auto shot : 3 balles en 1 s ; EN AKIMBO les balles alternent main principale / autre main sans être doublées (`GetBulletShooter`), les deux armes rechargent ; Coup d Petoir : 1 balle, 0 s (inchangé).
- `Source/YohohoSurvivor/Abilities/YSRollingShotAbility` (« Rolling shot », sous-classe du Coup d Petoir : mêmes réglages de tir et mêmes upgrades, Ricochet compris ; composant `RollingShot` de BP_Pistolet, hérité par BP_BattlePetoir, à la place du Coup d Petoir ; `Tools/EditorScripts/setup_rolling_shot.py`) : Ability Gun PewPew en 3 temps : 1) roulade `RollDuration` 0.2 s : le joueur garde le contrôle, BONUS DE VITESSE décroissant (vitesse mise tout de suite à MaxWalkSpeed × `RollSpeedMultiplier` 2 dans la direction du mouvement, puis multiplicateur qui retombe jusqu à `AimMoveSpeedMultiplier`, courbe `RollSpeedDecayExponent` 1 = linéaire ; sans touche de direction pressée, déplacement forcé à l opposé du curseur pris au lancement si `bForceMoveWithoutInput` : `GetForcedMoveDirection`, ajouté par le perso dans son Tick sur la machine qui le contrôle quand `Move` n a rien reçu (`LastMoveInputFrame`)) ; sur le serveur ET le client qui active (`OnActivationPredicted`) ; les multiplicateurs des actions se multiplient dans `UpdateMaxWalkSpeed` ; invulnérable (`IsGrantingInvulnerability`, + `ExtraInvulnerability` ; `AYSPlayerCharacter::IsInvulnerable` dans TakeDamage) ; traverse les pawns si `bRollThroughFoes` (capsule ignore ECC_Pawn pendant la roulade, sinon un NME devant l arrête net) ; anim (catégorie `Rolling Shot|Roll Anim` : `RollAnimTurns`, `RollAnimDuration`, `RollAnimEaseExponent`, `RollAnimTuckHeight`) = BodyPivot tourne vers la direction du mouvement (`GetBodyRoll`, `UpdateBodyPivot`) ; 2) visée `AimDuration` 0.25 s, vitesse × `AimMoveSpeedMultiplier` 0 (`GetMoveSpeedMultiplier`, `UpdateMaxWalkSpeed` à chaque Tick) ; 3) tir = rafale du Coup d Petoir droit devant (regard = curseur) ; akimbo : une seule roulade (main principale seulement dans `Fire`), l autre pistolet tire après `AkimboFireDelay`. Recharge après le tir (`GetCooldownDuration` = roulade + visée + rafale + Cooldown × CD reduction). `BlocksAllWeapons` : interrompt aussi les actions moins prioritaires de l AUTRE arme (sabre de Mouss) et les bloque pendant tout le Rolling shot (`GetPriorityGroup`). Recul : seulement par les balles (`PredictsFirstBullet` faux, `LastBulletTime`). Logs Verbose `[YSRollingShot]`.
- `Source/YohohoSurvivor/Abilities/YSCoupDPetoirAbility` : tir du pistolet (composant de BP_Pistolet ; tire depuis le Muzzle de l arme, Instigator = pawn qui la tient) ; visée assistée `AssistAimDistance` 1000 / `AssistAimAngle` 15° : `FindAssistTarget` = pawn le plus proche portant un HitTag du projectile, utilisée par le serveur au tir ; `Damage` (5) appartient à la capacité et est donné au projectile au spawn (`SpawnActorDeferred` + `SetDamage`).
- `Source/YohohoSurvivor/Abilities/YSCoupDSabreAbility` : attaque AUTO de BP_Epee (`IsAutomatic`). Serveur (TickComponent) : si prête et cible dans le cône `DetectionDistance` 300 / `DetectionAngle` 45° (regard du perso, `HitTags` Team.Foe) -> `StartAttack` (ReadyServerTime = durée anim + `AutoAtkCooldown` 0.8) + `MulticastActivated` (joué par tous, pas de prédiction). Akimbo : la main principale déclenche, l autre suit après `AkimboFireDelay`. Arme : `GetActiveAction()` (clic, icône UI, recul) / `GetAutoAction()`. ## Automatisation de l'éditeur (Python)

- Plugins `PythonScriptPlugin` + `EditorScriptingUtilities` activés : Claude crée/modifie des assets via des scripts dans `Tools/EditorScripts/`.
- Lancer un script qui modifie des assets / maps (éditeur fermé) : `UnrealEditor.exe <uproject> -ExecutePythonScript="<script.py>"` ; le script finit par `unreal.SystemLibrary.quit_editor()` et écrit un rapport dans `Saved/Logs/`. Un crash (0xC0000005) à la toute fin de la fermeture est connu et sans conséquence si les sauvegardes sont dans le log.
- `-ExecutePythonScript` ferme l éditeur dès la fin du script : pas de callbacks différés (tick). Captures de vérif : SceneCapture2D + `RenderingLibrary.export_render_target` en synchrone.
