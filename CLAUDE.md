# YohohoSurvivor

Jeu **top-down multijoueur en ligne (1 à 4 joueurs par partie)**, Unreal Engine **5.8**, C++.
Langue de travail avec l'utilisateur (Paul) : **français**.

## Build

- Paul travaille sur plusieurs PC : **aucun chemin absolu en dur**. Le projet = racine du dépôt (dossier de travail courant, `$PWD`). Le moteur se retrouve via le registre (installation Epic Games Launcher) ; si la clé est absente, demander à Paul où est UE 5.8 sur ce PC.
  ```
  $UE = (Get-ItemProperty "HKLM:\SOFTWARE\EpicGames\Unreal Engine\5.8" -ErrorAction SilentlyContinue).InstalledDirectory
  if (-not $UE) { $UE = "C:\Program Files\Epic Games\UE_5.8" }  # clé pas toujours créée par le launcher
  ```
- Toolchain : UE 5.8 exige **MSVC 14.50+** (Visual Studio 2026, composants dans `.vsconfig` ; 14.51 fonctionne). Avec MSVC 14.38/14.44 (VS 2022) le build échoue dans les en-têtes du moteur (erreur C7539 dans `ContainerAllocationPolicies.h`). Les `Target.cs` fixent `WindowsPlatform.CompilerVersion = "Latest"` : prioritaire sur le `%APPDATA%\Unreal Engine\UnrealBuildTool\BuildConfiguration.xml` global, qui peut forcer un vieux compilateur pour les autres projets UE de Paul (ne pas modifier ce fichier global). En PowerShell, **mettre entre guillemets** les arguments contenant des points (`"-CompilerVersion=…"`, `"-Project=…"`), sinon ils sont coupés.
  Exécutables : `$UE\Engine\Binaries\Win64\UnrealEditor.exe` / `UnrealEditor-Cmd.exe`.
- Compiler (éditeur fermé, ou sinon utiliser Live Coding Ctrl+Alt+F11 dans l'éditeur) :
  ```
  & "$UE\Engine\Build\BatchFiles\Build.bat" YohohoSurvivorEditor Win64 Development -Project="$PWD\YohohoSurvivor.uproject" -WaitMutex
  ```
- Régénérer la solution VS (après ajout/suppression de fichiers) :
  ```
  & "$UE\Engine\Build\BatchFiles\Build.bat" -projectfiles -project="$PWD\YohohoSurvivor.uproject" -game -rocket -progress
  ```
- Si `UnrealEditor` est ouvert avec Live Coding actif, le build en ligne de commande échoue : demander à Paul de fermer l'éditeur ou de lancer Live Coding.
- Les warnings C4996 venant de `Engine/` (Niagara, Character.h) sont connus et ne concernent pas notre code.
- Le packaging compile en **unity build** (plusieurs `.cpp` fusionnés) alors que les builds éditeur incrémentales non : les helpers `namespace { }` doivent avoir des noms uniques au projet (sinon C2084 seulement au packaging) ; mettre ceux d un fichier dans un namespace nommé (ex. `YSMainMenu::`).
- Après chaque modification C++, **compiler pour vérifier** avant de déclarer la tâche terminée.

## Structure

- `Source/YohohoSurvivor/` : module principal (classes de base du template Top Down : Character, GameMode, PlayerController).
- `Source/YohohoSurvivor/Variant_TwinStick/` : base la plus proche d'un « survivor » (projectiles, ennemis IA via StateTree, spawner, pickups, AoE). **Point de départ du gameplay.**
- `Source/YohohoSurvivor/Variant_Strategy/` : variante RTS du template, probablement à supprimer.
- Les dossiers de variantes sont dans `PublicIncludePaths` du `.Build.cs` : à mettre à jour si on déplace/supprime des dossiers.
- `Source/YohohoSurvivor/Player/YSPlayerCharacter` : personnage joueur (ZQSD/WASD ; les flèches sont réservées aux codes de triche, input créé à l'exécution, `MoveSpeed` réglable). Regarde le curseur (`bUseControllerRotationYaw`), strafe via `StrafeBlendSpace` joué en mode SingleNode (pas d'Anim Blueprint). Parent du BP `/Game/Placeable/Character/PlayerCharacter_mouss`.
- `Source/YohohoSurvivor/Player/YSPlayerController` : curseur viseur, calcule `AimLocation` (souris projetée sur le plan du pawn) et met la rotation de contrôle vers ce point ; le CMC l'envoie au serveur avec les mouvements.
- `/Game/Placeable/Character/Anims/BS_Player_Strafe` : BlendSpace 2D (X = direction -180..180 relative au regard, Y = vitesse 0..600 ; idle / marche 200 / course 600 dans 8 directions).
- Joueur (DA primitives) : `BodyPivot` (scene, origine capsule) porte `BodyMesh` (cylindre ; mesh squelettique vide, donc pas de strafe animé), `FaceDecal`, et les mains `LeftHand` / `RightHand` (scene, non scalées = points d attache des armes, `GetLeftHand()`/`GetRightHand()` ; position monde absolue calculée par `UpdateHands` : cible `HandLocation` (main droite, gauche = Y inversé) ou `HandLocation` de l arme si `bOverrideHandLocation`, rotation `HandRotation` (gauche = Yaw/Roll inversés) ou celle de l arme si `bOverrideHandRotation`, + oscillation Perlin `HandSwayAmplitude`/`HandSwaySpeed`, suivie avec retard `HandFollowSpeed`) avec leurs sphères `LeftHandMesh` / `RightHandMesh` (matériau copié de BodyMesh dans OnConstruction si `bHandsUseBodyMaterial`). Armes : `LeftHandWeapon` / `RightHandWeapon` = `UChildActorComponent` sur les mains (owner = perso, acteur enfant répliqué spawné par le serveur), classes données par le **set d arme** du perso (`WeaponSet`, catégorie 3C|Weapons : Data Asset `Weapons/YSWeaponSet` {`DisplayName`, `RightHandWeapon`, `LeftHandWeapon`} dans `/Game/Core/WeaponSets` : `DA_WeaponSet_SabrePistolet` (Mouss), `DA_WeaponSet_AkimboBattlePetoir`, `DA_WeaponSet_AkimboSabre` (obtenus par l upgrade de classe) ; `Tools/EditorScripts/setup_weapon_sets.py`), sinon par `LeftHandWeaponClass` / `RightHandWeaponClass` (tests, éditables seulement sans set) ; appliquées dans OnConstruction -> visuel dans l éditeur ; `GetHeldWeapons()`. Clic gauche = actions des deux mains ; main principale = droite ; akimbo (`IsAkimbo()` : même classe d arme dans les deux mains) : droite puis gauche après `AkimboFireDelay` de l ACTION de la main principale (catégorie `Akimbo` de chaque action : Coup d Petoir, Auto shot, Auto swing, réglables séparément) avec une **recharge unique** : la main droite se bloque `GetActivationLockDuration()` = recharge + délai akimbo, les deux mains redeviennent prêtes ensemble une fois les deux actions finies (Coup d Petoir et Auto swing ; icône comprise). Les upgrades ne dépendent plus des mains : Ability et Auto atk s appliquent à tout le set (voir upgrades). Debug : `YSFire` (comme un clic gauche), log Verbose `[YSAbility]` (heure d activation / prête). L icône UI suit la main droite, sinon la gauche. Les mains pivotent (yaw, `HandAimSpeed`) vers la cible de visée assistée du Coup d Petoir de leur arme (calculée depuis le regard du perso, donc identique sur toutes les machines ; en jeu seulement).
- `Source/YohohoSurvivor/Weapons/YSWeapon` : arme (Root, `Mesh`, `Muzzle`, `DisplayName`), `GetAction()` = premier `UYSAbilityComponent` de l acteur (ajouté dans le BP de l arme), `GetHolder()` = owner pawn. Recul : réglages sur chaque action de tir (`UYSCoupDPetoirAbility`, donc aussi l Auto shot, catégorie `Recoil` : `GetRecoilAlpha()` d après sa dernière activation, coup EaseOut `RecoilKickDuration`, retour EaseInOut `RecoilRecoverDuration`, `RecoilPitch`, `RecoilKickBack`), accéléré en rafale si la balle suivante de la même arme part avant la fin du recul (`bFitRecoilToFireRate`, `GetTimeToNextShot` calculé par le serveur et envoyé avec `MulticastBulletFired`, `RecoilTimeScale` ; l écart entre les tirs ne change pas, la dernière balle joue le recul normal ; log Verbose `[YSGun]`) ; `AYSWeapon::GetRecoil` prend l action de tir la plus récente ; le perso cabre la main et la recule le long de l axe de l arme, après le lissage. **Priorités des actions** (`ActionPriority` dans `YSAbilityComponent.cpp`, liste donnée par Paul : 1 Ability, 2 Auto atk) : par arme (les deux armes en akimbo), une action ne démarre pas (`CanStartByPriority`) tant qu une plus prioritaire est en cours (`IsActionInProgress` = `GetActionDuration()` depuis l activation, + `AkimboFireDelay` pour la main principale en akimbo ; Coup d Petoir / Auto shot : durée du recul ; Auto swing : son animation) ; en démarrant, elle interrompt les moins prioritaires (`CancelAction` serveur : anim arrêtée partout via `MulticastCancelled`, recharge rendue, main suivante de l akimbo annulée ; log Verbose « interrompue »). Réglages Akimbo / Recoil reportés depuis les armes par `Tools/EditorScripts/migrate_akimbo_recoil.py`. BP dans `/Game/Placeable/Weapons` : `BP_Arme` (base), `BP_Pistolet` (action `CoupDPetoir` : PetoirAMMO, 5 dégâts, recharge 1 s), `BP_Epee` (Auto swing en Auto atk), `BP_BattlePetoir` (enfant de BP_Pistolet : Coup d Petoir en Ability + composant `AutoShot` = `Abilities/YSAutoShotAbility` en Auto atk : sous-classe de Coup d Petoir, automatique, serveur : tire dès qu il est prêt et qu un NME est dans le cône de visée assistée, balle `/Game/Placeable/AMMO/PetoirAMMO_AutoShot` (enfant de PetoirAMMO : mesh 35 % plus fin, `m_PH_emissive_turboRed` ; le Rolling shot garde PetoirAMMO ; `Tools/EditorScripts/setup_auto_shot_ammo.py`), 20 dégâts, recharge 1 s, akimbo comme le sabre ; `Tools/EditorScripts/setup_battle_petoir.py` ; porté par aucun perso pour l instant). `UpdateBodyPivot` (visuel, toutes machines) : inclinaison autour des pieds vers la vélocité monde (`LeanMaxAngle` 30, `LeanDuration` 0.14 s, `LeanEasing` EaseIn, `LeanEaseExponent` 2) + sautillement vertical (`HopHeight` 10 cm, `HopDuration` 0.2 s à `MoveSpeed`, cadence proportionnelle à vitesse réelle / `MoveSpeed`, `HopEasing` EaseInOut). Paramètres du perso dans la catégorie `3C` (affichée en premier via `PrioritizeCategories`). Composant BP `Head Feature` (sphère, enfant de BodyPivot) porte `Bandana` = `UYSDanglingChainComponent` (`Player/YSDanglingChainComponent` : chaîne de cylindres en Verlet, gravité + poussée vers l arrière, segments transient en coordonnées absolues ; pose de repos dans l éditeur via tick éditeur, simulation en jeu). `FaceDecal` = `UYSFaceDecalComponent` (`Player/YSFaceDecalComponent`) : propriété `FaceTexture` sur le composant -> MID transient sur `M_FaceDecal` (`/Game/Art/Materials/Decals`), le DecalMaterial de base est restauré avant sauvegarde.
- `Source/YohohoSurvivor/Abilities/YSAbilityComponent` : base des capacités (recharge `Cooldown`, `TryActivate` côté client -> RPC `ServerActivate` -> `ExecuteAbility` sur le serveur ; `ReadyServerTime` répliqué, prédit côté client). Effets visuels : `GetTimeSinceActivation()` (temps local) mis à jour par prédiction chez le tireur et par `MulticastActivated` (Unreliable) chez les autres. ## Automatisation de l'éditeur (Python)

- Plugins `PythonScriptPlugin` + `EditorScriptingUtilities` activés : Claude crée/modifie des assets via des scripts dans `Tools/EditorScripts/`.
- Lancer un script qui modifie des assets / maps (éditeur fermé) : `UnrealEditor.exe <uproject> -ExecutePythonScript="<script.py>"` ; le script finit par `unreal.SystemLibrary.quit_editor()` et écrit un rapport dans `Saved/Logs/`. Un crash (0xC0000005) à la toute fin de la fermeture est connu et sans conséquence si les sauvegardes sont dans le log.
- `-ExecutePythonScript` ferme l éditeur dès la fin du script : pas de callbacks différés (tick). Captures de vérif : SceneCapture2D + `RenderingLibrary.export_render_target` en synchrone.
- Lecture seule / vérifications : `UnrealEditor-Cmd.exe <uproject> -run=pythonscript -script="<script.py>" -unattended`.
- API Python UE 5.8 : `unreal.ObjectRedirector` et `AssetTools.fixup_referencers` ne sont pas exposés ; filtrer les redirecteurs via `asset_data.asset_class_path.asset_name`.
